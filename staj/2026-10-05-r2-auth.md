# R2 — başarısız login ve eksik token kontrolleri

5 Ekim 2026. Amaç: login başarısızlığının sessizce anonim taramaya dönüşmesini
ve olmayan token'ın Authorization header'ına yazılmasını önlemek.

Kodda auth akışının yalnız bağlantı hatasında durduğu, null JSON değerinin
`None` metnine dönüştüğü ve eski cookie'nin başarı sayıldığı görüldü.
Yerel HTTP fixture'ında 401/403/429/500, eksik/null/boş ve yapısal token
değerleri ile önceden kurulmuş cookie karşı örnekleri oluşturuldu.
Form login başarısızlığında CLI durma ve ortak hata raporu kontrol edildi.

İlk odaklı koşuda üç test başarısızdı: yeni CLI testi olmayan `--url`
seçeneğini kullandı; iki mevcut test hata metninde step adını bekliyordu.
CLI girdisi düzeltildi; normal flow hata bilgisi korundu, auth hatası gizli
değer taşımayan sabit mesajla sınırlandı ve ilgili beklenti güncellendi.
Son odaklı sonuç 49 passed; tam paket sonucu VALIDATION.md içinde.
İlk tam koşuda eski stored fixture'ın başarılı login yönlendirmesi 404 döndü:
`/dashboard` handler'ı yoktu. Fixture'a oturum kontrollü dashboard eklendi;
HTTP hata guard'ı gevşetilmedi. İlk başarısız log yerel audit alanında korundu.

Öğrenilen: HTTP başarısı, cookie/header kurulumu ve doğrulanmış oturum/rol
farklı iddialardır. Bu teslim ilk guard maddesini kapatır; hedefe özel kontrol,
rate ve CSRF sıralaması açık. Çalışma süresi veya CVE başarısı iddia edilmez.
